# ฐานข้อมูลผลสลากกินแบ่งรัฐบาล ย้อนหลังทุกงวด ทุกรางวัล

เครื่องมือบรรทัดคำสั่ง + หน้าเว็บ สำหรับย้อนดูผลสลากกินแบ่งรัฐบาลตั้งแต่ **30 ธันวาคม 2549
ถึงงวดล่าสุด** โดยเก็บครบ **ทั้ง 9 หมวดรางวัล** (173 เลขต่องวด) ไม่ใช่แค่รางวัลที่ 1

ใช้ Python ไลบรารีมาตรฐานล้วน ไม่ต้อง `pip install` อะไรเลย ข้อมูลเก็บเป็น SQLite ไฟล์เดียว
หลัง `sync` ครั้งแรกแล้วใช้งานแบบออฟไลน์ได้

```
473 งวด · 81,829 เลขรางวัล · 2549–2569
```

## เริ่มใช้

```bash
python lotto.py sync            # ดึงข้อมูลทั้งหมด + ซ่อมงวดที่ต้นทางเสียให้เอง
python lotto.py serve           # เปิดหน้าเว็บที่ http://127.0.0.1:8777
```

ต้องมี Python 3.11 ขึ้นไป บน Windows แนะนำให้ใส่ `-X utf8` เวลาเรียกผ่าน cmd/PowerShell
เพื่อให้ภาษาไทยในหน้าจอไม่เพี้ยน:

```bash
python -X utf8 lotto.py info
```

## ตารางเทียบรายเดือนทุกปี

หัวใจของเครื่องมือนี้ — เอาเลขรางวัลของหมวดเดียวมาเรียงเป็นตาราง **แถว = ปี พ.ศ.** และ
**คอลัมน์ = เดือน** เพื่อกวาดตาเทียบเดือนเดียวกันข้ามปีได้ในหน้าจอเดียว

```bash
python lotto.py matrix last2            # เลขท้าย 2 ตัว
python lotto.py matrix first            # รางวัลที่ 1
python lotto.py matrix front3           # เลขหน้า 3 ตัว
python lotto.py matrix back3            # เลขท้าย 3 ตัว
python lotto.py matrix back3 --half late  # เอาเฉพาะงวดวันที่ 11 ขึ้นไป ตารางจะแคบลงอ่านง่ายขึ้น
```

```
รางวัลเลขท้าย 2 ตัว — เทียบรายเดือนทุกปี (ทั้งสองงวด)

ปี    ม.ค.      ก.พ.      มี.ค.     เม.ย.     พ.ค.      มิ.ย.     ก.ค.      ส.ค.      ก.ย.      ต.ค.      พ.ย.      ธ.ค.
2569  16/02     48/07     06/64     47/77     43/08     95/48     62/71     69/53     04/64     70/48
2568  51/23     51/50     54/32     36/85     06/87     20/06     91/26     50/63     31/58     77/61     87/37     22/52
2567  61        09/43     79/78     90/79     17/60     42/31     89/21     46/28     94/37     59/00     32/38     61/21
```

ในเดือนหนึ่งปกติออกรางวัล 2 งวด (ต้นเดือนและกลางเดือน) คั่นด้วย `/` บางเดือน —
ธันวาคมเป็นต้น — มี 3 งวด ตารางรองรับให้

บนหน้าเว็บ แท็บ **เทียบรายเดือน** ทำเรื่องเดียวกันแต่ดูง่ายกว่า: สลับหมวดได้ด้วยปุ่ม
พิมพ์เลขในช่อง "เน้นเลขที่มี" แล้วช่องที่มีเลขนั้นจะไฮไลต์ทั้งตาราง ชี้เมาส์เพื่อเน้นคอลัมน์เดือน
และคลิกเลขเพื่อกระโดดไปดูผลทั้งงวด

## คำสั่งอื่น

| คำสั่ง | ทำอะไร |
|---|---|
| `sync` | ดึง/อัปเดตข้อมูล |
| `info` | ภาพรวมฐานข้อมูล จำนวนงวดต่อปี |
| `draw [วันที่]` | ผลรางวัลทั้งงวด ครบ 9 หมวด (ไม่ใส่วันที่ = งวดล่าสุด) |
| `check <เลข 6 หลัก>` | ตรวจสลากกับงวดหนึ่ง |
| `history <เลข 6 หลัก>` | ย้อนดูว่าเลขนี้เคยถูกรางวัลงวดไหนมาแล้วบ้างทั้งคลัง |
| `matrix <หมวด>` | ตารางเทียบรายเดือนทุกปี |
| `search <รูปแบบ>` | ค้นเลขรางวัล (`?` = หนึ่งหลักใด ๆ, `*` = กี่หลักก็ได้) |
| `freq <หมวด>` | เลขที่ออกบ่อย/น้อยสุด |
| `gaps <หมวด>` | เลขที่หายไปนานสุด |
| `never <หมวด>` | เลขที่ยังไม่เคยออกเลย |
| `draws` | รายการงวด |
| `doctor` | ตรวจความครบถ้วนของข้อมูล |
| `repair` | ดึงงวดที่ข้อมูลเสียมาใหม่ |
| `export` | ส่งออก CSV/JSON |
| `serve` | เปิดหน้าเว็บ |

วันที่พิมพ์ได้หลายแบบ: `16/10/2569`, `2026-10-16`, `16102569`, `16 ตุลาคม 2569`, `16 ต.ค. 69`

## หมวดรางวัลที่เก็บ

| คีย์ | รางวัล | หลัก | เทียบแบบ | จำนวน |
|---|---|---|---|---|
| `first` | รางวัลที่ 1 | 6 | ตรงทุกหลัก | 1 |
| `near1` | รางวัลข้างเคียงรางวัลที่ 1 | 6 | ตรงทุกหลัก | 2 |
| `front3` | รางวัลเลขหน้า 3 ตัว | 3 | 3 หลักหน้า | 2 |
| `back3` | รางวัลเลขท้าย 3 ตัว | 3 | 3 หลักท้าย | 2 (ก่อน ก.ย. 2558 = 4) |
| `last2` | รางวัลเลขท้าย 2 ตัว | 2 | 2 หลักท้าย | 1 |
| `second` | รางวัลที่ 2 | 6 | ตรงทุกหลัก | 5 |
| `third` | รางวัลที่ 3 | 6 | ตรงทุกหลัก | 10 |
| `fourth` | รางวัลที่ 4 | 6 | ตรงทุกหลัก | 50 |
| `fifth` | รางวัลที่ 5 | 6 | ตรงทุกหลัก | 100 |

รวม 173 รางวัลต่องวดทั้งสองยุค ตั้งแต่ **1 กันยายน 2558** โครงสร้างเปลี่ยนจาก
"เลขท้าย 3 ตัว 4 รางวัล" มาเป็น "เลขหน้า 3 ตัว 2 รางวัล + เลขท้าย 3 ตัว 2 รางวัล"
โปรแกรมแยกยุคให้เองในคอลัมน์ `ruleset`

การตรวจสลากคิดรางวัลซ้อนกันได้ตามจริง — สลากใบเดียวถูกได้หลายหมวดในงวดเดียว

## เรื่องคุณภาพข้อมูลที่ควรรู้

สิ่งที่เจอจากการตรวจจริง ไม่ใช่ข้อสันนิษฐาน

- **งวด 16 มกราคม 2569 ในคลังหลักเสีย** ตัวเลขถูกตัดกลางและปนกับงวดอื่น และวันที่ผิดด้วย —
  งวดจริงคือ **17 มกราคม 2569** `repair --auto` ตรวจเจอ ดึงมาใหม่จาก sanook และจดการแก้วันที่
  ลงตาราง `corrections` ไว้ เพื่อให้ `sync` ครั้งต่อไปไม่ดึงงวดเสียกลับมาอีก
- **เลขซ้ำในหมวดเดียวกันเกิดขึ้นได้จริง** เช่น 2 พ.ค. 2551 เลขท้าย 3 ตัว ออก `001` สองรางวัล
  ตรวจแล้วตรงกันทั้งคลังหลักและ sanook จึงไม่ถือเป็นข้อมูลผิด `doctor` แยกเป็น "ข้อสังเกต"
  ไม่ใช่ "ปัญหา"
- **ข้อมูลงวดล่าสุดตรงกับ API ทางการเป๊ะทุกเลข** ใช้เป็นการสอบทานคลังหลักไปด้วย
- **ไม่เก็บเงินรางวัล** หน้าย้อนหลังของเว็บข่าวแสดงเงินรางวัล *ปัจจุบัน* ทับทุกงวด
  (งวดปี 2549 ก็ขึ้นรางวัลที่ 1 เป็น 6,000,000 บาท ซึ่งผิด — ยุคนั้นคือ 2 ล้านบาท)
  จึงตัดเรื่องเงินรางวัลออกทั้งหมด ดีกว่าเก็บเลขที่เชื่อถือไม่ได้

ตรวจสถานะได้เสมอด้วย `python lotto.py doctor`

## โครงฐานข้อมูล

```
draws        งวด: draw_date (PK), draw_date_th, ruleset, source, source_url,
                  prize_count, anomalies, updated_at
prizes       เลขรางวัล: (draw_date, category, slot) PK, number, digits
corrections  งวดที่ต้นทางลงวันที่ผิด: bad_date (PK), good_date, reason
meta         เวลาซิงก์ล่าสุด, แหล่งข้อมูล
sync_log     ประวัติการซิงก์
```

ไฟล์ฐานข้อมูลคือ `lotto.db` ข้าง `lotto.py` ย้ายที่เก็บได้ด้วย `--db`

## ข้อควรระวัง

ข้อมูลในนี้ใช้เพื่อ**ค้นย้อนหลัง**เท่านั้น การขึ้นเงินรางวัลต้องยึดประกาศของ
สำนักงานสลากกินแบ่งรัฐบาลเป็นหลัก

สถิติในเครื่องมือนี้เป็นการ**นับย้อนหลัง ไม่ใช่การทำนาย** การออกรางวัลแต่ละงวดเป็นอิสระ
จากงวดก่อนหน้า เลขที่ "ออกบ่อย" หรือ "หายไปนาน" ไม่ได้มีโอกาสออกงวดหน้าต่างจากเลขอื่น
