# Landing page แบบ scroll-driven video

หน้าเดียวจบ ไม่มี framework ไม่มี build step — เปิด `index.html` ได้เลย

## ใช้งาน

วางไฟล์สองอันนี้ไว้ที่ `landing/assets/`

```
assets/hero.mp4           วิดีโอพื้นหลัง (ดูวิธี encode ข้างล่าง)
assets/hero-poster.jpg    ภาพนิ่งเฟรมแรก ใช้ตอนวิดีโอยังไม่โหลดและบนมือถือ
```

ถ้ายังไม่มีไฟล์ หน้าก็ยังเปิดได้ปกติ — จะข้ามหน้าโหลดไปใช้พื้นสีเดียวแทน ไม่ค้าง

## encode วิดีโอให้ scrub ได้ลื่น

หัวใจคือ **ทุกเฟรมต้องเป็น keyframe** (`-g 1`) เพราะการ scrub คือการสั่งกระโดดไป
เวลาใดก็ได้ ถ้าเฟรมไหนไม่ใช่ keyframe เบราว์เซอร์ต้องถอยไปตั้งต้นที่ keyframe ก่อนหน้า
แล้วไล่ decode มา ทำให้กระตุก

```bash
ffmpeg -i ต้นฉบับ.mp4 \
  -an \
  -vf "scale=1920:-2,fps=30" \
  -c:v libx264 -profile:v high -pix_fmt yuv420p \
  -g 1 -keyint_min 1 -sc_threshold 0 \
  -crf 24 -preset slow \
  -movflags +faststart \
  assets/hero.mp4
```

| ตัวเลือก | เหตุผล |
|---|---|
| `-g 1 -keyint_min 1 -sc_threshold 0` | บังคับให้ทุกเฟรมเป็น keyframe — ข้อสำคัญที่สุด |
| `-an` | ตัดเสียงทิ้ง ไม่ได้ใช้ และลดขนาดไฟล์ |
| `-movflags +faststart` | ย้าย moov atom ไปต้นไฟล์ เบราว์เซอร์เริ่มเล่นได้ก่อนโหลดครบ |
| `-crf 24` | ทุกเฟรมเป็น keyframe ทำให้ไฟล์ใหญ่ขึ้นมาก ถ้าใหญ่เกินให้ขยับเป็น 26–28 |
| `fps=30` | 24–30 พอแล้ว ยิ่งสูงยิ่งหนักโดยไม่ได้ช่วยตอน scrub |

ภาพ poster:

```bash
ffmpeg -i assets/hero.mp4 -vframes 1 -q:v 3 assets/hero-poster.jpg
```

ขนาดไฟล์ที่เหมาะสมคือไม่เกิน 8–12 MB ถ้าเกินให้ลดความกว้างเหลือ 1440 หรือเพิ่ม `-crf`

## ปรับเนื้อหาและจังหวะ

แก้ที่ `SECTIONS` ในไฟล์เดียว — `time` คือวินาทีในวิดีโอที่ section นั้นต้องเล่นไปถึง

```js
const SECTIONS = [
  { time: 0,  eyebrow: "...", title: "...", say: "..." },
  { time: 4,  ... },
];
```

ค่าความหน่วงอยู่ที่ `TAU` (ค่าเริ่มต้น 0.42 วินาที) วิดีโอจะไหลเข้าที่ราว 1.3 วินาที
หลังหยุด snap ถ้าอยากให้ช้าลงให้เพิ่มค่า

## กลไกข้างใน

- **ไม่เซ็ต `currentTime` ตรง ๆ ตอน scroll** การเลื่อนแค่ขยับค่า `target` เท่านั้น
  แล้ว `requestAnimationFrame` ค่อย ๆ พา `current` เข้าหา `target`
- ใช้การลู่เข้าแบบอิงเวลาจริง `current += (target - current) * (1 - exp(-dt / TAU))`
  จึงให้ผลเท่ากันทั้งจอ 60Hz และ 120Hz ไม่ใช่คูณค่าคงที่ต่อเฟรมซึ่งจะเร็วช้าตามเครื่อง
- ข้ามการ seek เมื่อห่างจากเป้าหมายน้อยกว่า 0.004 วินาที และเมื่อวิดีโอกำลัง seek อยู่
  ไม่งั้นจะสั่งซ้อนกันจนกระตุก
- เลื่อนขึ้นก็ย้อนกลับเองโดยไม่ต้องเขียนเพิ่ม เพราะ `target` ลดลง
- `IntersectionObserver` ที่ threshold 0.55 เป็นตัวบอกว่า section ไหนกำลังอยู่ในจอ

## มือถือและ accessibility

จอกว้างไม่เกิน 820px, อุปกรณ์สัมผัส, หรือผู้ใช้ตั้ง `prefers-reduced-motion`
จะเข้าโหมดเบา — วิดีโอเล่นวนปกติ ไม่ผูกกับการเลื่อน (ถ้า autoplay ไม่ผ่าน
ก็จะเหลือภาพ poster) และ scroll-snap ถูกปิดเมื่อผู้ใช้ขอลดการเคลื่อนไหว

ปุ่มลูกศรขึ้น/ลงและ PageUp/PageDown เลื่อนทีละ section ได้
